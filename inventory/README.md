# MPC program hardware-status ledger

`program-status.csv` is the maintained listening and hardware-validation ledger
for the writable SD-card mirror. The structural fields are generated by
`scripts/audit_sd_programs.py`; the remaining fields are updated after testing
on the MPC Key 37.

Allowed `hardware_status` values:

- `untested`
- `pass`
- `partial`
- `fail`

Use `favorite` for a simple yes/no shortlist and `scratchpad_role` for one of
the standard startup roles such as drums, percussion, bass, keys, lead, loops,
texture, or capture. Put observable tuning, range, velocity, volume, loop,
missing-sample, and reload behavior in `notes`.

Structural `pass` only means that the XPM is readable and all of its declared
local sample references resolve to nonzero files. It is not a musical or
hardware pass.

`semantic_verdict` records the local note/velocity and audio-boundary simulator
result. `simulation_scope=testing` identifies isolated fixtures whose failures
do not block the production deployment gate. See `docs/testing-framework.md`.
